## 性能证据

完整原片 1920×1200、60fps、实际解码 95955 帧：

| 配置 | 时间 | 结果 |
|---|---:|---|
| 历史 OpenCV/32 workers | 约 786 秒 | 595 暂停、0 速度段 |
| 新 FFmpeg/4 workers + 内容区域校准 | 124.50 秒 | 583 暂停、700 速度段、698 保留区间 |

两轮同时改变内容区域与评分缓存，约 6.3 倍提速不能归因于单项优化，也不能承诺通用倍数。

受控 1800 帧短片每组 3 次中位：OpenCV/4 workers 为 14.488 秒，FFmpeg/4 workers 为 3.288 秒；峰值私有提交分别为 4132MiB 与 4141MiB，不等于驻留物理内存。新完整分析未进行同等峰值内存采样，不声称全片内存指标已验收。

识别侧：4 个诊断源帧的人工核验结果与全片输出吻合，但这不构成独立准确率测试；不宣称 98% 分类准确率或 99% 暂停召回率。

## 已知限制

- 0.2x 过场假阳性（如关卡标题）仍存在，需人工复核；未完成全片标注与战斗/选择界面门控。
- 严格静止规则默认关闭，仅作为实验选项，不替代完整操作保护验收。
- 新宿主源入出点语义、音频精度与 overwrite 兜底未完成真机验收，结果可能为 partial。
- 浏览器剪后播放是跳切试听，不保证帧精确剪接或长期音画同步；不兼容编码的播放代理需可选 FFmpeg。
- 干净 Windows 安装、其他 Premiere 版本、Ctrl+C/强杀断电、回滚期间二次文件占用与 15 分钟总超时未全覆盖验收。
- 用户历史多个 CEP 同 ID 副本的加载优先级不自动治理。

## 尚待完成的验收

1. 独立标注集上的漏删/误删时长、操作保护区与速度逐类 precision/recall。
2. 非战斗过场误识别门控、稳定窗口与操作区域判定的广泛验证。
3. 新界面真实 CEP 可见画面、交互延迟、连续剪接及长时间音画同步。
4. 新宿主输出源入出点语义、非零标记、最终保存并关闭重开。
5. 干净 Windows 安装、离线包及可选 FFmpeg 的完整部署体验。

上述未通过项不计为完成；源码与自动测试通过不等于所有产品目标均通过。
